# Implementation Rules

1. 새 기능보다 기존 구조를 먼저 확인한다.

2. 같은 UX는 같은 CSS와 같은 내부 시스템을 사용한다.

3. 가장 단순한 구현을 우선한다.

4. 기존 공통 기능을 먼저 재사용하고, 새 Engine은 마지막 선택이다.

5. 같은 로직을 여러 곳에 구현하지 않는다.

6. 데이터는 하나의 Source of Truth만 가진다.

7. Runtime과 Editor의 역할을 섞지 않는다.

8. 기능 추가와 리팩토링은 가능하면 분리한다.

9. 구현 전 재사용할 공통 시스템과 영향 범위를 먼저 보고한다.

10. 같은 문제를 두 번 해결하지 않는다.

11. Task가 끝날 때마다 `docs/99_TASK_REPORT.md`에 작업 결과를 작성한다.

12. 사용자가 같은 개념으로 인식하는 기능은 내부 구조도 가능한 한 하나의 공통 시스템으로 구현한다.

13. `runtime/project-default-state.json`은 프로젝트 저장 데이터다. 파일이 매우 크므로 특별한 요청이 없는 한 전체를 읽지 않는다. 항상 필요한 key만 부분 조회한다. 설계 문서 대신 `10_SRC_MAP`, `11_DATA_MODEL`, `13_ACTION_MODEL`을 우선 참고한다. `project-default-state.json`은 실행 데이터 확인이 필요한 경우에만 사용한다.

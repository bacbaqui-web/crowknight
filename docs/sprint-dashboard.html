2. 직전 완료 Task 보고

Task 이름

모바일 반응형 조작 UI 추가

Task 목표

  • 화면 폭 변경 시 주인공의 가로 중앙 배치를 유지하고 세로 카메라 높이는 보존한다.
  • 820px 이하에서 좌우 모바일 터치 패드를 표시한다.
  • 조합 입력과 멀티터치를 기존 입력 시스템에 연결한다.

완료 내용

  • `index.html`에 Q/W/Space 및 네 방향 버튼을 추가했다.
  • 모바일에서도 데스크톱과 같은 세로 카메라 높이와 safe area를 적용했다.
  • 기존 `data-hold-code` 바인딩을 재사용해 멀티터치 조합을 지원한다.
  • 왼쪽은 원을 네 부채꼴 터치 영역으로 나눈 고정 방향키로 개편했다.
  • 오른쪽 아래에는 4분의 1만 보이는 큰 Q 버튼을 배치했다.
  • Q 곡선을 따라 SPACE/W/빈 E 슬롯을 30도 간격으로 구성했다.
  • Q를 직전 위치보다 50px 올리고 방향 조작을 1.1배, W/SPACE를 1.2배 확대해 간격과 각도를 다시 계산한다.
  • 모바일 렌더링 배율은 세팅 및 수식 결과보다 0.2 낮게 적용한다.
  • 타이틀·사망·결과 화면에서는 조작 패드를 숨긴다.
  • 모바일 결과 화면의 말풍선을 제거하고 점수·입력·아이콘·랭킹 순서로 재배치했다.
  • 데스크톱 결과 말풍선은 결과창보다 앞에 두고 패널 바깥의 계산된 여유 공간에만 생성한다.
  • 점수를 생존 초×5 + 잡몹×100 + 보스×1,000으로 변경하고 상단 HUD와 결과 화면에 세 항목을 표시한다.
  • 상단 HUD를 축소하고 공통 조작법 버튼, 중앙 안내 패널, 입력 시 재개되는 일시정지를 추가했다.
  • 기존 Firebase 랭킹 17개를 처치 8회당 보스 1회로 추정 분리해 새 점수 산식으로 일괄 재계산했다.
  • 배포 버전 감지, 안전한 갱신 보류, 1회 자동 재접속과 Service Worker 캐시 정책을 추가했다.
  • 버전 확인을 5분 간격으로 조정하고 Service Worker 재검증을 no-cache로 최적화했다.
  • 설정·캐릭터·이펙트·배경 준비 전에는 LOADING 버튼을 표시하고 완료 후 PLAY를 활성화한다.
  • 배포 버전을 1.01v 형식으로 전환하고 결과창의 버전 버튼에서 게임 내부 업데이트 내역 모달을 연다.

남겨둔 범위

  • 내장 브라우저 미제공으로 모바일 화면 자동 스크린샷 QA는 진행하지 못했다.
  • 실제 휴대전화에서 회전 및 멀티터치 조합을 수동 확인해야 한다.

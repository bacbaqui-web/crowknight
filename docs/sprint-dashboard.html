Group Edit을 임시 Transform 대상처럼 다루고, Group 전용 차이는 Adapter로 모았습니다.

여러 파츠 선택, Property 입력, Canvas move/rotate/scale 자동 QA가 통과했습니다.

직전 Task 보고

완료된 작업

  • ✅ Group Transform Adapter 추가 그룹 전용 이동/회전/스케일 분배 계산을 한 파일로 모았습니다.
  • ✅ Group Pose 전용 파일 제거 예전 `group_pose_editor.js` 역할을 Adapter로 옮겨 이름과 책임을 맞췄습니다.
  • ✅ 공통 Transform 진입점 유지 Canvas drag는 Group이면 Adapter로 넘기고, 일반 Part는 기존 공통 계산을 그대로 사용합니다.
  • ✅ Property 입력도 Adapter 사용 Group X/Y/R/S/O 입력이 같은 Adapter를 통해 선택된 여러 파츠에 나눠 적용됩니다.

무슨 뜻인가

  • → Group은 저장 객체가 아님 그룹 자체를 저장하지 않고, 선택된 여러 Action part에 결과만 나눠 씁니다.
  • → 차이는 Adapter에 둠 여러 파츠에 값을 분배하는 특수 계산만 Group Adapter에 남깁니다.
  • → 공통화 방향이 선명해짐 Group Edit은 “복수 선택 → 임시 Transform Target → 결과 분배” 역할로 좁아졌습니다.
  • → 큰 파일 흡수 금지 공통 기능은 큰 controller에 더 넣지 말고 작은 helper로 유지해야 합니다.

자동 QA 결과

  • Group 선택 / Property 표시 PASS: Action 첫프레임에서 선택 그룹 2와 X/Y/S/R/O가 표시됐습니다.
  • Group Property stepper PASS: X, S, R, O 값이 stepper 입력으로 변했습니다.
  • Group Canvas handle PASS: move, rotate, scale handle drag 후 표시값이 변했습니다.

검증 결과

  • ✅ Group Adapter 연결 확인 Property 입력과 Canvas drag가 `group_transform_adapter.js`를 사용합니다.
  • ✅ 오래된 파일 참조 제거 `group_pose_editor.js` 코드 참조를 제거하고 문서의 JS 지도도 갱신했습니다.
  • ✅ 기능 범위 유지 Stage/HUD/Background와 저장 구조는 건드리지 않았습니다.
  • ✅ Headless 자동 QA 통과 Group 선택, Property stepper, Canvas move/rotate/scale이 통과했습니다.

주의사항

  • ⚠ 사용자 눈검사는 선택 자동 QA는 통과했습니다. 커밋 전 화면 감각만 한 번 볼 수 있습니다.
  • ⚠ Group 결과 분배는 Adapter 책임 여러 파츠에 값을 나눠 쓰는 특수 동작은 Adapter 경계에 남아 있습니다.
  • ⚠ Group은 Action 전용 이번 Sprint에서는 Setup/Effect/Stage/HUD의 Group 편집은 만들지 않았습니다.
  • ⚠ 커밋 안 함 변경분은 작업트리에 남아 있습니다.
